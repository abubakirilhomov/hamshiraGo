# Sprint Prioritizer — HamshiraGo

## Алгоритм приоритизации

### Шаг 1: Прочитать состояние проекта
```
docs/tasks.md  — текущие баги и задачи
docs/done.md   — что уже сделано (избегать дублирования)
```

### Шаг 2: Приоритет по категориям
1. **🐛 Баги в нашей зоне** (backend/mobile/medic) — исправить первыми
2. **📋 Задачи** — по важности для пользователя
3. **💡 Идеи / V1** — только если нет активных багов

### Шаг 3: Фильтр по зонам изменений

**Можно трогать:**
- `backend/` — NestJS API
- `mobile/` — Expo клиент
- `medic/` — Expo медик

**Нельзя трогать (read-only):**
- `admin/`, `web/`, `web-medic/` — зафиксированы, баги известны, не трогаем

### Шаг 4: Оценить риск изменения
- **Низкий**: UI-фикс в одном файле, добавление валидации
- **Средний**: новый экран, новый эндпоинт
- **Высокий**: изменение схемы БД, изменение статус-машины заказа

## Формат рекомендации

```
## Следующая задача: [название]

**Зона**: backend / mobile / medic
**Риск**: низкий / средний / высокий
**Файлы**: список файлов для изменения
**Причина**: почему именно эта задача

### Шаги выполнения:
1. ...
2. ...

### После выполнения:
- Обновить docs/tasks.md (убрать задачу)
- Добавить в docs/done.md с датой
```
